# Code Signing Server Example

## General Informaton

The F&S Code Signing Server implements a example on how to sign Images with Yocto, without needing to have the private keys available in the local filesystem. The server is implemented as a docker container that holds the necessary Tools and users with certain roles and permissions. The tools need to be provided by the user before generation of the container. This is explained in more detail in the **Setup** chapter.

**Important Note: This Code Signing Server Example project is only meant for demonstration purposes, not to be used in a production environment.**

### Tools

| Name                  | Purpose                                                                                     |
------------------------|---------------------------------------------------------------------------------------------|
| F&S Secure Boot Tool  | Front End for the NXP Code Signing Tool. Handles Key and CSF generation for F&S Boot Images |
| NXP Code Signing Tool | NXP Tool to sign Images for use with HAB and AHAB                                           |

### Users

| Name   | Login                             | Purpose                                                                   |
---------|-----------------------------------|---------------------------------------------------------------------------|
| root   | su in active admin session        | For administration with root priviledge                                   |
| admin  | ssh login                         | Default user for administration, no full root priviledge as default       |
| client | ssh login with limited permission | Interface for the build system. Loin gets forced onto the dispatch script |
| signer | no login                          | Uses the tools. Gets called by client with a sudo rule                    |

### Scripts

| Name              | Purpose                                                                                                  |
--------------------|----------------------------------------------------------------------------------------------------------|
| dispatch          | Implements the API for the client user. Can transfer Images, sign Images list and clean output area.     |
| sign-and-serve.sh | Calls the tools that sign the Images. Used as the target of the sudo rule, to seperate client and signer |

## Setup

To setup the server you can simply call the setup.sh script. On your first call you have to provide the locations of your F&S Secure Boot Tool, your IMX Code Signing Tool and your ssh pulic key. The ssh key is used for communication between your building environment and the signing server. It can be generated with the following command:

```
ssh-keygen -t ed25519
```

Afterwards you can call the setup script:

```
./setup.sh --start cst-dir <your cst directory> fs-sb-tool-dir <Your F&S Secure Boot Tool directory> ssh-pub-key <your ssh public key>
```

This will copy the tools and files to docker/tools/. If you input the options again, it will first delete the staged files and copy again, otherwise reuse them as the are in the directory.

**The Dockerfile will handle cerificate generation for demonstration purposes. These are not meant for production.**

### (Optional) provide Keys and Certificates

If you want to provide your own certificates, you can do so by uncommenting the respective part in the Dockerfile and providing the files in their respective locations.

## Activating Code Signing in Yocto

In Yocto, signing of Images is part of a class, that can be activated by adding the following line to your local.conf

```
DISTRO_FEATURES:append = " fus-image-signing"
```

You should also set your signing servers IP address

```
SIGNING_SERVER_ADRESS = <Your IP Address>
```

## stopping, restarting or deleting

You can alsays stop the signing server

```
./setup.sh --stop
```

If you want to restart the server you can just run 

```
./setup.sh --start
```

You can also delete the server. Please note that this removes all files of the container, includingthe certificates and keys, generated by it.

```
./setup.sh --delete
```
